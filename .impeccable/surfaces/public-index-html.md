# Dashboard

## Scope and mode

Replace the visual system across the dashboard, item detail, and connection setup. Mode: Operate.

## Audience and task

The owner reviews personally relevant Azure DevOps work. They need attention-worthy stale items first, then a reliable way to find the wider set of items they created, edited, commented on, or were assigned. Preserve all current filters, item details, sync, setup, source links, and local/read-only behavior. GitHub is a future goal, not a current integration.

## Direction contract

THESIS: Departure Board. Bring stalled work to the front, then keep the whole queue easy to scan.
OWN-WORLD: A deep navy rail and attention panel frame a cool, light work surface. Navy anchors navigation and primary actions; blue marks interaction; red and amber carry attention meaning. Use tabular figures, crisp columns, and legible workhorse typography.
STORY: Recognize the workspace and sync state, scan stale items by elapsed age and last-changed date, then search and filter the complete workload. Opening an item reveals its context and full activity.
FIRST VIEWPORT: A standard workspace shell frames the content. The heading and sync action lead into a dark attention board with aligned columns for age, work item, project, state, and last changed. Three compact workload counts sit below; search and familiar filters lead into the complete table. Keep breakdowns collapsed. On narrow screens the rail becomes a top strip and the table becomes labeled work-item rows.
SIGNATURE: A continuous navy attention board uses precise column rhythm, tabular age, an amber elapsed-time cue, and a small red stale marker. Show only real dates and elapsed time; never imply due dates or flight schedules.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
